# Security Policy

## Reporting a vulnerability
Please report security issues privately — do not open a public issue for anything sensitive.
- Use GitHub Security Advisories ("Report a vulnerability" on the Security tab).

Include a description, steps to reproduce, the affected version/commit, and impact. We'll
acknowledge within a reasonable time and keep you posted on a fix.

## Scope
VibeStick is an early-preview hobby project. Security-relevant areas:
- The local bridge HTTP service (binds 0.0.0.0:8765 by default for LAN access; protected
  state and control endpoints require a shared `VIBE_STICK_BRIDGE_TOKEN`).
- Credential handling (ASR API keys and Wi-Fi credentials) — kept local, never committed or logged.
- Recording and transcript handling — complete transcripts are not persisted and recordings
  are deleted after processing by default.
- The StickS3 firmware.

## Good to know
- Run the bridge only on networks you trust, and set `VIBE_STICK_BRIDGE_TOKEN`
  (auto-generated by `scripts/setup.sh`).
- StickS3-to-Mac traffic uses local HTTP without transport encryption. Never expose port
  8765 to the internet or use the bridge on public/untrusted Wi-Fi.
- Keep real secrets in the gitignored `.env` and
  `firmware/sticks3/include/vibe_stick_secrets.h` — never commit them.
- See `docs/PRIVACY.md` for the complete local storage, LAN, cloud-ASR, and credential model.

## Supported versions
This is a fast-moving preview; only the latest `main` / release receives fixes.
